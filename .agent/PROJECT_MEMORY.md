- An ordinary live Appender scope holds ordinary Connection admission for the complete awaited body; a transaction Appender uses transaction operation admission instead. Both reuse the same public Appender, native registry, and Connection owner, while `NativeAppender` strongly retains `NativeConnection` while DuckDB's Appender holds only a weak client context.
- Appender row calls perform cancellation/count/full normalization before actor entry, recheck cancellation on the actor immediately before synchronous native mutation, and serialize each complete row as one actor-owned native operation. Concurrent public row calls therefore cannot interleave columns.
- Wrong Appender row width and unsupported Swift values are caller-local/recoverable before native mutation. The first native primitive/end-row failure is terminal, is synchronously consumed/discarded, is stored as authoritative first-terminal truth, and cannot be converted to a successful scope by catching it inside the body.
- Body error/cancellation paths explicitly discard still-buffered Appender data before ordinary-admission release. Ambiguous native clear failure conservatively fail-closes the Connection before release; later work receives `.connectionUnusable`.
- Inherited same-Connection ordinary Connection/Statement work, transaction start, and nested Appender are rejected while the Appender body is live; separate Connections remain independent. Deliberately TaskLocal-erased external same-Connection work is treated as external and may form a caller dependency cycle if awaited from the exclusive body.
- Normal escaped Appender use after scope finalization returns `.appenderEnded`, while fail-closed Connection state may dominate.
- Ordinary Appender scope is explicitly non-atomic. Pinned DuckDB may auto-flush earlier rows before the Swift body ends, so later body error/cancellation cannot promise rollback of already flushed data. Transaction Appender is rollback-safe under the explicit outer transaction, including auto-flushed batches; a failed scope makes that transaction rollback-only, and a caught arbitrary body failure may surface `appenderTransactionAborted` at finalization.

Same-scope transaction query/execute, transaction-bound Statement, and nested transaction Appender are rejected.
