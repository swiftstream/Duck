- Async execution uses DuckDB pending execution, cooperative Swift cancellation checks, and same-owner `duckdb_interrupt` when cancellation is observed at the implemented active-pending boundaries. Cancellation surfaces as Swift `CancellationError`; no instantaneous preemption guarantee is made for a synchronous native C call already in progress.

Supported scalar families are null, Bool, signed/unsigned 8/16/32/64-bit integers, Float, Double, Foundation.Decimal, String, Foundation Data BLOB, UUID, exact Int128/UInt128 through macOS 15+/iOS 18+ availability-gated bridges, PureDate, PureTime, DateTime, Foundation.Date as exact TIMESTAMPTZ, and shared `Interval` as exact DuckDB `INTERVAL`. Native one-dimensional `Value.list` and immediate keyed `Value.structure` are accepted current composite P0 surfaces. `Value.Kind.decimal == 22`, `Value.Kind.list == 23`, and `Value.Kind.structure == 24`, with all prior Kind IDs stable. LIST supports exact scalar/ENUM children, NULL parent/children, prepared/Appender/result paths, and Codable Array properties. Recursive LIST/STRUCT nesting, fixed ARRAY, MAP, UNION, and other recursive composites remain deferred. - Prepared Date binding accepts only targetless or resolved `TIMESTAMPTZ`, with exact per-value equality and no tolerance/silent rounding. Appender Date conversion and typed-value creation occur during whole-row preflight before native mutation; deterministic Date failure mutates zero native columns and is recoverable, while native append/end-row/finalization failure remains terminal. NativeResult reads `duckdb_timestamp.micros` and rejects infinity, non-finite, or otherwise non-exact Date values through `invalidResult`; `ResultColumn` preserves TIMESTAMPTZ identity.
- Shared `Interval` is the public semantic type with no duplicate Duck Interval type. `Value.Kind.interval == 21` and IDs `0...20` remain unchanged; `Value.interval`, `get(Interval.self)`, `intervalValue`, and Row Interval conveniences are accepted. `NativeIntervalCodec` owns exact finite conversion: months/days use `Int32(exactly:)`, microseconds stay `Int64`, and mixed-sign/non-normalized components are preserved. Infinities and out-of-native-range months/days survive generic normalization and reject at native Prepared/Appender boundaries. Prepared binding calls direct `duckdb_bind_interval`; Appender conversion happens during whole-row preflight and is recoverable on deterministic failure, followed by direct `duckdb_append_interval`, whose native failure remains terminal. NativeResult uses validity-first direct `duckdb_interval` vector access, preserves the legitimate all-minimum triple, and never infers validity from `duckdb_get_interval` sentinels. Ordinary SQL uses plain Interval/Optional transport while `Value.interval` uses dynamic routes. The transaction `.binding` first-reason identity remains protected.
- Exact Decimal current state uses production `DecimalExactCodec.swift` byte-identical to the accepted DCT128-v1 codec SHA `f0eeadd40c0bd0f5ac5e80622643d7762927d94a8d971d229938e16806f4ce08`. `NativeDecimalAdapter` owns exact explicit-target and targetless natural W/S policy; explicit `DECIMAL(W,S)` must fit exactly, targetless zero is `DECIMAL(1,0)`, no implicit rounding/truncation or Double/Float transport is permitted, and nonfinite values reject deterministically. Prepared Decimal uses direct `duckdb_bind_decimal` with owned parameter logical-type inspection/destruction. NativeResult is validity-first and reconstructs W1...4 SMALLINT, W5...9 INTEGER, W10...18 BIGINT, and W19...38 HUGEINT exactly with reverse word revalidation. - Public `DatabaseError` distinguishes database/connection opening, preparation, binding, execution, unsupported binding/result type, invalid-result failures, reusable-Statement template/argument/ownership/usability failures, transaction lifecycle/scope failures, Appender scope/row/finalization/cleanup failures, and terminal `.connectionUnusable` state.
- Query-centered `SQLable.query(on:)` / `.execute(on:)` are thin delegates to the same Connection engine.
- Public reusable `Statement` is a `Sendable` final class created by `Connection.prepare`; it strongly retains its originating `Connection`, stores no native handle, and identifies its actor-owned native prepared statement through an internal registry id.
- `Connection.prepare` supports a fixed-only direct SQL query and a builder form whose private `Statement.Parameter` values define dynamic arguments. Fixed and dynamic native slot order comes from one SQL Duck preparation with same-render unsafe-value provenance.
- Every reusable execution clears prior native bindings and fully rebinds the immutable fixed/dynamic layout before using the existing pending execution engine. There is no automatic reprepare or public native parameter-index API.
- Ordinary `Statement.query` / `execute` use the existing Connection ordinary FIFO scheduler. Explicit `Statement.query(on:)` / `execute(on:)` use the existing owning-DuckTransaction operation FIFO without acquiring the outer ordinary lease.
- Statement/DuckTransaction owner mismatch is rejected before operation registration. Matching-owner transaction execution registers before argument-count/type normalization so caller-local failures participate in rollback-only first-reason semantics and cannot false-commit when caught.
- All four public Statement async operations retain the Statement through completion; deinit only schedules idempotent registry removal on the originating Connection actor, preventing the Statement's own cleanup from racing its queued/native-active operation.
- A fail-closed Connection dominates Statement execution with `.connectionUnusable`; clear-bindings failure is separately contained as a terminal Statement-local tombstone and does not auto-reprepare or fail-close the whole Connection.
- Public scoped `Appender` is a `Sendable` final class supplied by either `Connection.appender(to:)` or `DuckTransaction.appender(to:)` for `DB.Table` and `DB.Schema.Table`; schema- and catalog-qualified targets share `DB.Schema.Table`, with catalog qualification carried by `DB.Schema`, and each target form also offers fixed `columns: [String]` selection. It stores no native handle and exposes only complete-row `append(...)`, relative to the table or selected list.
- Fixed selected-column Appender setup occurs before body entry and rows; the nonempty list defines immutable append-argument order. Omitted columns use DuckDB DEFAULT or NULL, whereas a selected `nil` is explicit NULL. Invalid/duplicate/unknown/generated names reject creation. Existing no-`columns:` overloads retain complete-table-row behavior. Selected-row width and deterministic whole-row preflight failures are recoverable before native mutation; native failures retain terminal scope semantics. Ordinary auto-flush visibility, transaction rollback-only/finalization, pool-lease ownership, and same-identifier canonical-runtime Observation boundaries are unchanged.
- An ordinary live Appender scope holds ordinary Connection admission for the complete awaited body; a transaction Appender uses transaction operation admission instead. Both reuse the same public Appender, native registry, and Connection owner, while `NativeAppender` strongly retains `NativeConnection` while DuckDB's Appender holds only a weak client context.
- Appender row calls perform cancellation/count/full normalization before actor entry, recheck cancellation on the actor immediately before synchronous native mutation, and serialize each complete row as one actor-owned native operation. Concurrent public row calls therefore cannot interleave columns.
- Wrong Appender row width and unsupported Swift values are caller-local/recoverable before native mutation. The first native primitive/end-row failure is terminal, is synchronously consumed/discarded, is stored as authoritative first-terminal truth, and cannot be converted to a successful scope by catching it inside the body.
- Body error/cancellation paths explicitly discard still-buffered Appender data before ordinary-admission release. Ambiguous native clear failure conservatively fail-closes the Connection before release; later work receives `.connectionUnusable`.
- Inherited same-Connection ordinary Connection/Statement work, transaction start, and nested Appender are rejected while the Appender body is live; separate Connections remain independent. Deliberately TaskLocal-erased external same-Connection work is treated as external and may form a caller dependency cycle if awaited from the exclusive body.
- Normal escaped Appender use after scope finalization returns `.appenderEnded`, while fail-closed Connection state may dominate.
- Ordinary Appender scope is explicitly non-atomic. Pinned DuckDB may auto-flush earlier rows before the Swift body ends, so later body error/cancellation cannot promise rollback of already flushed data. Transaction Appender is rollback-safe under the explicit outer transaction, including auto-flushed batches; a failed scope makes that transaction rollback-only, and a caught arbitrary body failure may surface `appenderTransactionAborted` at finalization.
- Transaction Appender holds one transaction operation across the awaited body and finalization/cleanup. Same-scope transaction query/execute, transaction-bound Statement, and nested transaction Appender are rejected. Fail-close teardown/precedence is accepted current behavior; deterministic whole-row preflight failures remain recoverable, while native append/end-row/finalization failures remain terminal.
- Current Appender row values are `Value`, recursive Optional/NULL, Bool, signed/unsigned 8/16/32/64-bit integers plus Int/UInt, Float, Double, Foundation.Decimal, String, Foundation Data, UUID, availability-gated Int128/UInt128, PureDate, PureTime, DateTime, Foundation.Date, and `Interval`. Foundation.Date maps only to TIMESTAMPTZ under exact per-value semantics; finite Interval maps only to DuckDB INTERVAL with exact Int32 month/day narrowing and Int64 microseconds; Decimal maps only to exact DuckDB `DECIMAL(W,S)`. Temporal/Interval/Decimal conversion and typed-value construction occur for the whole row during preflight before native mutation, so deterministic failure is recoverable and mutates zero columns; native Appender append/end-row/finalization failure remains terminal. Nested/complex expansion remains gated.

## Reviewed Direction

- The library baseline is Swift 6.3+.
- Intended platforms are iOS 15+, macOS 12+, Linux, Android, and Windows; each support claim requires actual platform/toolchain evidence.
- DuckDB integration stays behind a thin public-C-API boundary unless separately reviewed evidence justifies another boundary.
- High-level database APIs use Swift structured concurrency, `async`/`await`, and truthful actor/Sendable ownership while preserving independent concurrency where DuckDB semantics permit it.
- SQL remains the mandatory query-construction layer. Duck must not grow a competing SQL DSL or ordinary String execution API.
- README executable usage uses SQL only; plain SQL may appear only as explanatory comparison, and raw SQL is documented only as an explicit escape hatch.
- The desired database UX is concise and Swift-native while keeping concrete database/connection ownership visible.
- Development proceeds capability by capability. Transactions, reusable prepared Statements, ordinary and transaction Appender modes, the complete exact scalar/temporal/Interval/Decimal Value vertical, native one-dimensional LIST, immediate keyed native STRUCT, Codable / Model Layer, Migrations, Observation / Reactive Queries, and Connection Pooling are implemented accepted current state with their required validation/closure evidence. Observation owns actual successful result `IsReadOnly` truth, native READ ONLY refreshes, `.tables([])` for successful empty dependencies, bounded latest-state coalescing, same-identifier canonical-runtime invalidation, managed + flat manual DuckTransaction finalization/publication, and ordinary/Transaction Appender visibility integration. Current ordinary non-read-only query/Statement execution still publishes conservative Database-wide invalidation, so an unrelated ordinary write may rerun a table-scoped observation before equal-result suppression; general column-/predicate-/changed-row-aware invalidation is not implemented. This is tracked as deferred v1.2 technical debt `OBSERVATION-SCALABILITY-V1_1`. Observation does not promise DuckDB catalog rebind for already prepared handles, event-log delivery, cross-identifier/cross-process invalidation, or cross-process/file observation. Fixed selected-column Appender is accepted current state with public README/publication/source-owned skill closure complete. Other advanced Appender surfaces, recursive/composite Value expansion beyond the closed LIST/STRUCT P0 boundaries, unrelated future integrations, Android follow-up, and additional platform validation remain separately gated.
- The maintainer explicitly wants reusable-prepared-statements and Appender explanations/examples preserved for future articles/publications. `.agent/FUTURE_PUBLICATIONS.md` records implemented API/source-material truth; publication backlog entries still do not authorize another capability or imply a release/publication event.
- Repository work is role-specific and interface-agnostic: coordinator/reviewer and independent-auditor sessions use their configured approved repository interfaces, while a direct local implementation/validation executor uses its own local repository/filesystem/Git/shell tools for executable fallback work. A local executor must not depend on a coordinator/auditor-only repository bridge, and transient handoffs/prompts own any concrete tool names for the current environment.
